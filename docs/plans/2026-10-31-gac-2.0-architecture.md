## Projects

| Project | Kind | Notes |
| --- | --- | --- |
| `Gac.Shared` | lib | DTO contracts, command signing (HMAC-SHA256), replay guard, roles/permissions, module interface, pipe protocol, class-mode preset schema + validator, preset ECDSA signing, TLS pinning helpers. No module code. |

## Key flows

1. **Server install**: generate RSA-2048 self-signed cert (SAN = host name + IPs), ECDSA P-256 preset-signing key, enrollment code; create DB; open one firewall port; register service.
2. **Enrollment (agent & console)**: client connects with a "capture" validator that records the server cert SHA-256. `GET /api/enroll/hello?nonce=` returns `HMAC(code, thumbprint || nonce)`. Client verifies against the thumbprint it saw (defeats MITM without the code), then pins it. Agent then `POST /api/enroll` with the code and receives `agentId` + 32-byte key + preset public key.
3. **Agent → server auth**: every request carries `X-Gac-Agent`, `X-Gac-Timestamp`, `X-Gac-Signature = HMAC(key, ts \n method \n path \n sha256(body))`.
4. **Server → agent commands**: signed at delivery time (when the agent polls) so offline PCs do not receive already-expired commands. Agent rejects bad signature, `IssuedAt` older than 5 minutes (or > 1 minute in the future), and replayed command IDs (persisted ring of recent IDs).
5. **Results**: written to a local queue directory first, uploaded with exponential backoff (30 s … 15 min).
6. **Console auth**: username/password → opaque session token (stored hashed), 8 h sliding expiry. Every endpoint checks `Permission` on the server.
